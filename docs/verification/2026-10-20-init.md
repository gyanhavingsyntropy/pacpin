# Current-feature onboarding redesign

## Behavior and ownership

`pacpin init` / `setup`, including automatic interactive first launch, now use
one preservation-aware questionnaire. It configures privilege/AUR tools,
repository and delay policies, orphan review, upgrade cache defaults, alias
maintenance and Flatpak/Nix/Pipx participation. Sources compilation/optimization,
conditional hooks, declarative inventory, temporary apps, per-command scope,
scratch/cache capabilities and custom manager flags are explained alongside
their owning files and commands.

The wizard clones current configuration. Explicit manager overrides remain
owned by `managers.toml`, including custom manager selections. It does not
install packages, discover remote updates, run recipes or execute hooks.
`wizard/{preferences,prompts,review}.rs` separate questions from presentation;
`config/setup.rs` owns bounded exact snapshots, the shared config lock, main-file
backups and the existing atomic writer. Existing supplemental files are never
rewritten. Their absence is filled only after explicit final approval.

EOF/q cancel and invalid answers retry. Non-TTY setup and irrelevant options
fail visibly. Cancellation does not fall through into first-launch alias work.
Fresh alias maintenance defaults off; explicit opt-in writes only after saving.
Reset can back up malformed main TOML but does not bypass invalid supplements.
Any byte change to any of the four files during interaction refuses the save.

Removed the obsolete wizard-only Flatpak/Nix/Pipx wrappers and duplicate
preview/upgrade code. Existing capability tests now use the actual configured
provider, including canonical Flatpak preparation and unsupported Nix/Pipx
preparation defaults. No production manager operation was changed.

## Disposable Garuda terminal verification

Reproduction (inside the documented guest with its Kitty socket):

```sh
PACPIN_DISPOSABLE_VM=1 python /tmp/verify_init_vm.py /tmp/pacpin \
  --output /tmp/pacpin-init-review-3
```

The script uses a normal real Kitty shell, not a PTY substitute; test HOME and
all XDG paths are isolated. It captures rendered screen/scrollback and parses
saved TOML/backups. Guest tools are probed for executable availability only;
no real or fixture package manager commands/hooks are invoked by setup.

An initial reconfiguration check exposed an unintended change to the legacy
global integrations preference when explicit manager settings owned selection.
The fix preserves that preference and adds a regression. Narrow prompts wrap
correctly; the verifier normalizes wrapped text when locating confirmation.

Final run: **22/22 passed**, exit status 0. Scenarios:

| Group | Checked outcomes |
| --- | --- |
| Fresh / narrow / first launch | Default preferences, all four valid files, alias maintenance off; normal and 44-column real terminal |
| q / EOF / Ctrl-C / final decline | No config or alias writes; Ctrl-C returns 130; shell remains usable |
| Invalid answers | Retry tool/helper/yes-no inputs; corrected pkexec preference persists |
| Alias opt-in | Shell unchanged until final approval, then exactly one alias and notification marker |
| Delays and Flatpak | Reject negative days; create 5-day kernel rules; enable only selected Flatpak legacy integration |
| Reconfigure / reset | Preserve rules, manifests, embedded/supplemental sources/hooks and explicit/custom manager settings; exact old main backup, including malformed reset input |
| Four concurrent edits | New comment-only changes to main/managers/sources/hooks all refuse save with status 1; no overwrite or backup creation |
| Invalid option / help / malformed files | Visible errors with nonzero status, help without writing, reset cannot bypass invalid supplements |
| Noninteractive / templates only | Interactive init refuses redirected stdin; config init creates just the three supplemental files |

Results (local verification artifact), per-case screen/scrollback captures and
