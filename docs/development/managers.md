### Scope every feature to the managers involved

- Native/AUR repository pins represent explicit qualified targets or selected repository companions; unqualified AUR fallback and helper-discovered dependencies must never create pins. Derive pin intent from the original request separately from helper routing, then persist only successful targets. Preserve existing user pins. AUR VCS metadata is not a reliable downgrade target: recognize standard VCS suffixes on names and split-package bases, suppress stale-version downgrades/pin-sync rebuilds, and preserve normal upgrades plus stable/native pin synchronization. Test these cases together whenever changing routing or version policy.

- Keep README, configuration templates and reference docs current with public changes before the local commit. State exact tested capabilities and limits; simulated adapters do not establish a real Flatpak/Nix/Pipx application upgrade.
- User-editable config files belong together beside config.toml: managers.toml, optional sources.toml and hooks.toml. Preserve legacy inline recipes/hooks, reject cross-file duplicate names, and never copy merged supplemental definitions back into config.toml during automatic pin changes. Explicit initialization creates missing files; read-only commands never create or overwrite them.
- Manager commands are literal argument arrays; never implicitly invoke a shell or interpolate metadata into shell programs. Validate schema, placeholders and target identities before approval. Custom checks return bounded JSON; custom verification must establish the exact approved installed target. Core pacman/AUR retain typed adapters, ALPM planning, locks, space checks and privilege ownership; arbitrary command overrides cannot bypass these contracts.
- Namespace custom upgrade flags as --MANAGER.FLAG. Consume them before native/AUR forwarding, respect option values and '--', preview all added arguments/actions, and reject unknown or out-of-scope flags. Upgrade flag actions run only after successful work for their manager; standalone `pin manager NAME --FLAG` actions have their own preview/approval and do not imply a package upgrade.
- External scratch/cache capabilities are explicit. RAM/disk command variants require a declared scratch footprint and shared quota/inode/RAM checks. TMPDIR selects temporary work only; never promise that it relocates a daemon's build directory or final store. Do not equate pruning installed runtimes, deleting Nix generations or garbage collection with cache removal. No-cache arguments compose with scratch variants, and cleanup is limited to successful invoked managers.
- Check and execute the same Nix profile model; never fall back to nix-env after an arbitrary failure. Preserve Flatpak installation, full ref and approved commit; update only approved Pipx environments using their actual distribution identity. Failed discovery, malformed metadata, timeout and worker panic are explicit incomplete checks, never an empty successful result. Stop later external providers on installation/unknown failure. Upgrade --keep-going may skip a declared unsupported option during preflight; runtime continuation retains its positively verified AUR-to-Sources contract.
- Reuse source HTTP agents without widening credential forwarding or redirects. Native metadata callers share a resolved pacman-conf snapshot; invalidate after foreground commands/config-changing actions before fresh planning. Recent history uses bounded reverse reads and preserves chronological output and malformed-tail handling.

- Derive status rows, completion messages, prefetch, cleanup, and flags from the approved transaction and the manager actually invoked.
- Show approved AUR work as Pending while earlier managers run; do not imply that its helper has already started. Omit unplanned AUR upgrades and never claim AUR completion without real success. Apply the same rule to native packages, Sources, Flatpak, Nix, and other integrations. Named update checks describe actual discovery and never establish installation success.
- Provider capabilities must be explicit and default to unsupported. Do not assume a generic integration supports source downloads or source scratch handling.
- Upgrade scope controls must exclude unrelated checks, refreshes, downloads, status rows and cleanup. `--sources-only` / `--aur-only` never refresh native repositories; AUR-required build dependencies are a distinct possible native transaction. Keep pacpin controls out of helper arguments, respecting option values and `--` targets.
- Scratch flags select temporary storage only. Forced RAM/disk must match the filesystem, retain quota/inode/RAM checks and root installation checks, and never silently fall back to the other medium. AUR build size is unknown: do not describe its starting check as a full footprint guarantee. Configure Paru through its supported clone directory and makepkg environment, unprivileged, with explicit rejection for unsupported helpers.
- Review invocation controls across every public command when adding them; document applicable roles and reject irrelevant combinations before side effects. Preserve option values and application arguments after `--`, including privilege selectors. Native repository run/try owns archive download and extraction in one capacity-checked workspace. Check actual archive paths before extraction; never infer millions of required inodes from payload byte size. Update README and docs/cli-controls.md together.
- Ephemeral execution distinguishes preparation from app runtime: use the shared footer for aggregate downloads/checking/extraction and restore the terminal before the app owns it. Preserve run's normal home and try's isolation. Scratch overrides for an installed-only target or a backend-owned store require explicit capability handling. For Pipx run --no-cache, own its environment, shared libraries and pip/UV caches privately and clean only that workspace; the backend freshness flag alone does not establish immediate cleanup.
- Capability skips are opt-in with `--keep-going`: use the required typed provider contract and shared upgrade preflight, project the eligible inventory before approval/counts/hooks/prefetch, preserve reasons and skipped footer state, and perform no actions/cleanup for skipped managers. Invalid configuration, missing executables, bad metadata and capacity failures remain fatal. Overall skips stay incomplete/nonzero and defer orphan cleanup; no-work managers are not validated for irrelevant options.
- Runtime continuation is opt-in with `--keep-going`, only after positive build-failure evidence and unchanged native database/log with healthy installed dependencies. Native/unknown failures and interruptions stop the run. Providers default to unsupported; Sources validate exact approved plans, transitive and actual archive dependencies and the prepared native transaction before continuing. Keep the original failed stage and nonzero result visible; never mark it completed or purge its cache because an independent package succeeded.
- Distinguish downloading, checksum verification, packaging, installation, and successful completion. A completed prefetch is not a completed upgrade.
- Source-code builds are explicit format=source recipes with local literal commands. Inherit makepkg flags unless overridden in build.optimization; never silently add costly LTO/PGO settings. Resolve release Git tags to commits before approval. Source archives retain SHA-256 checks. Build dependencies/tools fail preflight before other transactions, and build failures stop before package installation. Keep compilation out of prefetch and guarded AUR-failure continuation; verify native/prebuilt paths still work.
- Keep pacman output and hooks visible. Background workers must not write directly into a foreground manager's terminal display.
- Use the shared progress renderer for foreground installation and upgrade commands. Native, AUR, Sources, Flatpak, Nix, and Pipx should identify the active manager consistently. Add a concurrent Sources row only to native/AUR operations with actual source work; a shared renderer does not authorize sharing manager-specific flags, scratch rules, or cleanup.
- Preserve the invoking terminal session and inherited stdin across foreground commands. Sudo caches credentials per terminal; creating a new controlling PTY for each stage causes repeated password prompts. Relay output without taking ownership of authentication input or changing sudoers on the host.
- The shared footer owns cursor positioning. Disable a manager's competing terminal UI through its supported plain-output mode (Flatpak: FLATPAK_FANCY_OUTPUT=0), preserve normal messages and prompts, and verify a subsequent command works without stray cursor-position replies in shell input.
- On resize, clear the previous footer within the visible viewport before reserving the new region or forwarding child bytes; never draw stale dimensions or let footer text wrap into normal output. Use the same visible cleanup coordinates during suspension and teardown. Verify repeated native/Sources resize transitions, exact native history and hook lines (without leftover footer suffixes), and preserve the terminal's wrap mode afterward.
- For interactive sudo operations, the user expects fresh authentication once per pacpin invocation and reuse throughout that invocation, including AUR builds. Reset only the current terminal ticket lazily before the first actual privileged operation, keep it renewed without prompting during long operations, and leave read-only commands, dry runs, other privilege tools, and other terminals unaffected. Test consecutive invocations in the same terminal with an existing ticket.
