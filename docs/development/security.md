### Security and resource checks

- Native try/run may reuse an exact installed package for an explicit --installed request or when an unqualified target has no configured repository candidate. Select executables from the requested package's inventory (usr/bin, usr/sbin, toolkit bin/sbin beneath usr/lib or opt), never an arbitrary PATH match or downloaded dependency's executable. Keep try's isolation and run's explicit host execution; explicit repository targets and dependency/download failures must not silently fall back. Report an existing installed version before testing a repository candidate, preserve installed files, and verify a newer test version leaves the installed version unchanged.
- Document output persistence separately from scratch placement. Native run preserves normal app writes; try owns private home/tmp and exposes only eligible current directories, read-only by default. Do not promise home-tree/system-directory mounts or persistent private sandbox data. Verify host/project writes survive and private sandbox writes disappear; scratch flags do not relocate generated documents or cap app memory.

- Audit locked Rust dependencies with `cargo audit` when reviewing security. Record the advisory database revision and distinguish advisories from yanked or unmaintained releases. This does not audit system libraries such as libarchive or libalpm.
- Bound remote metadata and cache reads before parsing, including decompressed HTTP bodies. Deserialize only fields needed by the caller. Reject control characters in remote versions and sanitize cached display fields too.
- Resolve symlinks component by component in filesystem order, including intermediate links before `..`. Lexical normalization and checking only the last component do not prove confinement. Fail on inspection errors; test intermediate-link escapes, absolute links, cycles and safe dangling links.
- Hash regular files through the download boundary with bounded streaming buffers. Refuse symlink/device/FIFO inputs and keep cancellation checks; checksum correctness must not depend on external program output or filename escaping.
- Cache writes must atomically replace the destination without following a file symlink. Check private directory ownership, bound reads, use exclusive private temporary files, and remove them on failure. Test an unrelated sentinel file and cache hits to cover both safety and avoiding repeated discovery.
- Security review evidence must state the trust boundary and verification limits. Checksums establish integrity, not publisher trust; successful unit tests are not a claim that every package manager or integration was exercised.
- Source build commands are trusted local configuration executing upstream code with user permissions; no sandbox is implied. Git metadata selects exact commits before approval; fetch disables unrelated credentials/hooks and restricts protocols. Compile outputs and declared executables must stay inside the private tree. Failed makepkg scratch cleanup may restore directory access only through pinned owned directory descriptors, without following symlink targets or crossing filesystems.
